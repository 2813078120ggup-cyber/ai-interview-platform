# 2026-07-25 讯飞虚拟人播放与语音兜底修复

## 背景

面试间显示“讯飞虚拟人已接入”，但实际没有画面也没有声音。根因是前端把后端 `enabled=true` 直接视为可播放成功；同时虚拟人视频元素被设置为静音，且讯飞返回 FLV/RTC 等非普通 mp4 流时浏览器无法直接播放。

## 本次调整

- 前端接入 `mpegts.js`，支持讯飞返回的 FLV 直播流播放。
- 普通虚拟人视频不再默认 `muted`，避免有视频流但无声音。
- 增加虚拟人流地址类型判断：
  - mp4/webm/ogg：直接播放。
  - flv：使用 FLV 播放器播放。
  - 可嵌入 http 页面：iframe 展示。
  - hls/rtc/rtmp 等当前不可播流：显示明确提示，并自动使用浏览器语音朗读兜底。
- 后端在未返回 `streamUrl` 时不再把响应标记为可播放接入，避免前端误判为成功。
- 前端不再截断虚拟人错误信息，方便定位讯飞错误码。

## 验证

- `frontend-react`: `npm run build` 通过。
- `backend`: `mvn -q -DskipTests package` 通过。

## 注意

如果讯飞返回 `22105 avatar error`，通常是数字人/VMC 引擎初始化或形象授权问题，需要在讯飞控制台确认接口服务、虚拟人形象 ID、发音人/音色和授权状态。
