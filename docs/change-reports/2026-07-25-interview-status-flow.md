# 2026-07-25 面试状态流转功能调整报告

## 本次目标

优先实现核心功能闭环：统一面试结束、AI 报告生成、报告可查看、管理员标记通过等状态流转，减少管理端和候选端状态展示不一致的问题。

## 修改内容

1. 后端新增面试状态常量：
   - `5`：报告生成中
   - `6`：已出报告
   - `7`：未通过

2. 调整面试结束流程：
   - 候选人或管理员结束面试后，面试状态从“进行中”进入“报告生成中”。
   - 自动评分任务只处理“报告生成中”的面试。
   - 自动评分与报告生成成功后，面试状态更新为“已出报告”。
   - 自动评分最终失败后，面试回退为“已结束”，保留管理员手动生成报告入口。

3. 调整管理员标记通过逻辑：
   - 仅允许“已结束 / 已出报告 / 未通过”的面试标记为“已通过”。
   - 禁止“待开始 / 进行中 / 报告生成中”的面试直接标记通过。

4. 调整手动生成报告逻辑：
   - 管理员可对“已结束 / 报告生成中 / 已出报告 / 未通过”的面试生成或重新生成报告。
   - 手动生成成功后，面试状态更新为“已出报告”。

5. 前端统一状态显示：
   - 新增 `frontend-react/src/lib/interview-status.ts` 作为统一状态文本、颜色和行为判断入口。
   - 管理端面试列表、工作台、面试回顾、候选人详情改为使用统一状态工具。
   - 候选人面试大厅、面试间结束判断改为使用统一状态工具。
   - “报告生成中”状态下候选人端显示不可点击的“报告生成中”按钮，避免误进入报告页。
