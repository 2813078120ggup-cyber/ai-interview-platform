# 2026-07-25 语音朗读误报失败修复报告

## 背景

面试房间中语音朗读实际已经成功启动，但页面仍显示「语音朗读未能启动，请点击“重新朗读本题”后重试。」。

## 问题原因

浏览器 `SpeechSynthesis` 在开始新朗读前会调用 `cancel()` 取消上一段朗读。部分浏览器会把上一段朗读的取消事件触发为 `onerror`，错误类型通常是 `interrupted` 或 `canceled`。旧逻辑没有区分这类“主动取消”与真实失败，导致朗读成功后仍显示错误提示。

## 本次改动

1. 为每次朗读增加 `speechToken` 标识。
   - 只处理当前这一次朗读的事件。
   - 忽略上一段朗读延迟返回的错误事件。

2. 忽略主动取消类错误。
   - `interrupted`
   - `canceled`

3. 在朗读真正开始时清理旧的语音朗读错误提示。

4. 在朗读结束时清理当前朗读错误提示。

5. 调用 `speechSynthesis.resume()`，减少浏览器语音队列被暂停导致的兼容性问题。

## 验证结果

- 已执行 `npm run build`
- TypeScript 编译通过
- Vite 生产构建通过
- 构建仅保留 chunk 体积提示，不影响运行

## 关于是否接入语音模型

当前浏览器原生语音朗读适合本地演示和轻量使用，但生产环境建议逐步接入专门的语音模型：

- DeepSeek 继续负责面试官提问、追问、评分和总结。
- 语音模型负责 TTS 朗读和 ASR 语音转文字。

这样声音质量、稳定性、多端一致性和可控性都会更好。
