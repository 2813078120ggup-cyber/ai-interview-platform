# 2026-07-25 系统设置 Provider 操作按钮逻辑优化报告

## ① 问题

系统设置页面中，不同类型的 Provider 使用了同一组操作按钮。例如语音识别服务也展示“设为文字”，大模型也展示“设为语音”，容易让管理员误操作。

## ② 为什么是问题

- Provider 类型不同，支持的能力不同。
- ASR 服务只适合作为语音识别/语音默认链路，不应作为文字大模型。
- 当前默认 Provider 如果被直接删除，会导致后续面试或语音功能缺少默认服务。
- 未启用或未配置服务地址时执行测试，结果没有业务意义。

## ③ 如何修改

- 新增 Provider 能力判断：
  - `llm` 类型只允许设置为文字默认。
  - `virtual-human`、`speech`、`asr`、`tts` 类型只允许设置为语音默认。
- 未启用 Provider 时禁用测试和设默认按钮。
- Base URL 未配置时禁用测试按钮，浏览器语音除外。
- 当前文字默认或语音默认 Provider 禁止删除，要求先切换默认项。
- 删除按钮保留边框按钮风格，并使用危险色提示，避免视觉上过于突兀。
- 已是默认项时按钮显示为“文字默认”或“语音默认”，并禁用重复操作。
