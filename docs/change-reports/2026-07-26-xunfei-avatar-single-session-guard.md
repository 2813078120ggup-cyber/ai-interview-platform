# 讯飞虚拟人单会话与资源释放修复

日期：2026-07-26  
范围：`frontend-react/src/pages/interview-room.tsx`

## 问题

讯飞在线虚拟人仅有一条授权路数时，React 状态更新尚未渲染完成前的重复点击、开发模式下的生命周期重放，或页面刷新后未释放的会话，都可能并发执行两次 `avatar.start()`。第二条会话会被服务端以 `11203 / avatar authentication failed` 拒绝。

## 修复

- 增加基于 `useRef` 的启动互斥锁；不依赖异步更新的 `virtualLoading` 状态。
- 增加启动尝试序号。路由切换、卸载或刷新后，旧异步启动即使晚到也不会重新激活会话。
- 组件卸载、`pagehide`、`beforeunload` 时同步调用 SDK 的 `stop()` 和 `destroy()`，优先释放讯飞会话路数。
- 启动失败时仅清理由当前尝试创建的运行时，避免旧请求覆盖新会话状态。

## 说明

`/v1/virtual-human/sdk-config` 仅返回短期签名 URL 与 SDK 配置，本身不会占用在线虚拟人授权路数；实际占用发生在 `avatar.start()` 成功建立远端会话时。

代码修复后，若控制台在只打开一个面试页面、只点击一次“启动虚拟人”的情况下仍返回 `11203`，需在讯飞交互日志中终止所有“持续中”的链路，并确认该 AppID 的在线虚拟人授权路数仍有效。

## 验证

- 在同一页面快速连续点击“启动虚拟人”，Network 中最多允许一条启动链路进入 SDK `start()`。
- 刷新或离开面试页面后，讯飞交互日志中的会话应被终止；再次进入页面可申请新会话。
- `npm.cmd run build` 通过后再进行浏览器联调。
