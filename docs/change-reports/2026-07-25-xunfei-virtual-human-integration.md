# 2026-07-25 讯飞虚拟人接入报告

## 本次目标

在现有 AI 面试间中接入讯飞虚拟人能力，让 AI 面试官提问、追问和题目朗读可以优先驱动讯飞虚拟人播报；讯飞配置缺失或调用失败时，自动降级为本地数字人与浏览器语音朗读，避免影响面试流程。

## 已完成内容

1. 后端新增虚拟人播报接口：
   - `POST /v1/virtual-human/speak`
   - 支持接收播报文本、面试题 ID 和已存在会话 ID。
   - 返回虚拟人启用状态、会话 ID、拉流地址和降级说明。

2. 后端新增讯飞虚拟人客户端：
   - 按讯飞开放平台 Web API 的 HMAC-SHA256 鉴权规则生成签名。
   - 支持启动虚拟人会话。
   - 支持向虚拟人会话发送文本播报指令。

3. 系统设置 Provider 增强：
   - 自动补充“讯飞虚拟人” Provider。
   - 虚拟人类型下将字段语义调整为：
     - `聊天模型` → `接口服务 ID`
     - `语音模型` → `发音人 / 音色`
     - `虚拟人形象` → `虚拟人形象 ID`
   - Provider 测试时会检查 AppID、APIKey、APISecret、接口服务 ID 和 avatarId 是否完整。

4. 面试房间接入：
   - 朗读当前题目或 AI 追问时，先调用后端虚拟人播报接口。
   - 如果讯飞返回可播放 `streamUrl`，前端展示虚拟人视频流。
   - 如果未配置或调用失败，继续使用本地 AI 面试官卡片和浏览器语音朗读。

## 需要管理员填写的参数

在 `管理后台 → 系统设置 → 讯飞虚拟人` 中填写：

- APPID
- APIKey
- APISecret
- 接口服务 ID
- 虚拟人形象 ID / avatarId
- Base URL
- 发音人 / 音色（可选，默认 `x4_lingxiaoxuan_oral`）

## 安全说明

- 密钥只提交到后端，由后端加密保存。
- 前端只展示脱敏后的密钥，不直接暴露 APISecret。
- 讯飞接口调用由后端统一签名代理，避免浏览器端泄露密钥。

## 验证结果

- 后端 `mvn -q -DskipTests package` 通过。
- 前端 `npm run build` 通过。

## 后续建议

- 拿到真实 avatarId 和接口服务 ID 后，在系统设置中完成配置并点击“测试”。
- 若讯飞返回 RTMP 流，浏览器不能直接播放时，建议增加 HLS/WebRTC 转码或使用讯飞官方 Web SDK 承载虚拟人画面。
